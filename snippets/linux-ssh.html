Linux ssh Command Examples

SSH (Secure Shell) is the standard protocol for securely accessing remote servers, transferring files, and creating encrypted tunnels. Mastering SSH commands is essential for any developer or system administrator working with remote infrastructure.

Linux ssh Remote CLI
Connecting
Basic SSH connection 
ssh user@hostname
Opens an interactive shell on the remote host. Replace user with the remote username and hostname with the server's IP or domain name. SSH defaults to port 22 and will prompt for a password if no key is configured.
Connect on a non-standard port 
ssh -p 2222 user@hostname
The -p flag specifies a non-default port. Servers are often configured to listen on a non-standard port (e.g., 2222) as a basic security measure to reduce automated scanning. You can set this permanently in ~/.ssh/config.
Connect with a specific private key 
ssh -i ~/.ssh/mykey.pem user@hostname
The -i flag specifies the path to the private key file (identity file). This is required for cloud servers like AWS EC2 that use PEM key files instead of passwords. Ensure the key file has correct permissions: chmod 400 ~/.ssh/mykey.pem.
Run a single command remotely 
ssh user@hostname 'ls -la /var/www'
Executes a command on the remote host and exits immediately, without opening an interactive shell. Quote the command to prevent local shell expansion. Output is printed to your local terminal, making this useful in scripts.
File Transfer
Copy a file to a remote server 
scp localfile.txt user@hostname:/remote/path/
Securely copies a local file to a remote directory using SCP (Secure Copy Protocol). SCP uses SSH for transport and is available on all systems with SSH. The destination path must be a directory if copying a single file.
Copy a file from a remote server 
scp user@hostname:/remote/file.txt ./
Copies a file from the remote server to the current local directory. Reverse the source and destination compared to uploading. Use -P 2222 (uppercase P for scp, unlike lowercase p for ssh) to specify a non-default port.
Recursively copy a directory 
scp -r ./localdir user@hostname:/remote/path/
The -r flag copies an entire directory tree recursively. For large transfers or when bandwidth efficiency matters, prefer rsync which can resume interrupted transfers and skip unchanged files.
Sync directory with rsync over SSH 
rsync -avz -e ssh ./localdir user@hostname:/remote/
rsync with the -e ssh flag uses SSH as the transport. Flags: -a (archive mode, preserves permissions/timestamps), -v (verbose), -z (compress during transfer). rsync only transfers changed files, making it ideal for deployments.
Tunneling and Config
Local port forwarding 
ssh -L 8080:localhost:80 user@hostname
Forwards your local port 8080 to port 80 on the remote server. After running this, browsing to http://localhost:8080 on your machine reaches the remote server's port 80. Useful for accessing services behind firewalls or on private networks.
Background SSH tunnel 
ssh -fN -L 8080:localhost:80 user@hostname
The -f flag puts SSH in the background before executing the command, and -N tells SSH not to execute a remote command (just maintain the tunnel). This creates a persistent background tunnel without occupying a terminal.
Copy public key to remote server 
ssh-copy-id user@hostname
Appends your local public key (~/.ssh/id_rsa.pub by default) to the remote server's ~/.ssh/authorized_keys file. After this, you can log in without a password. Use -i ~/.ssh/mykey.pub to specify a different key.
Check key fingerprint 
ssh-keygen -lf ~/.ssh/id_rsa.pub
Displays the fingerprint of a public key. Use this to verify that your public key matches what is registered on a server or cloud provider. The output includes the key length, fingerprint hash, comment, and key type.

How to Use

  1. Generate an SSH key pair with ssh-keygen -t ed25519 -C "your@email.com" if you don't have one yet.
  2. Copy your public key to servers with ssh-copy-id user@hostname to enable passwordless login.
  3. Create an ~/.ssh/config file to store host aliases, ports, and key paths for frequently accessed servers.
  4. Set permissions: chmod 700 ~/.ssh and chmod 600 ~/.ssh/authorized_keys — SSH refuses to use keys with loose permissions.
  5. Use the -v flag for verbose output when troubleshooting connection issues.

Frequently Asked Questions

What is the difference between SSH keys and passwords?

SSH key authentication uses a cryptographic key pair (public + private key) instead of a password. The private key never leaves your machine, making it significantly more secure than passwords which can be brute-forced. Most production servers and cloud providers (AWS, GCP, Azure) disable password login entirely and require SSH keys.

How do I set up an SSH config file for easier connections?

Create or edit ~/.ssh/config with entries like: Host myserver, HostName 192.168.1.100, User ubuntu, IdentityFile ~/.ssh/mykey.pem. After this, you can connect with just ssh myserver instead of the full command. This also works with scp and rsync.

Why does my SSH connection keep timing out?

Idle SSH connections are often dropped by firewalls and NAT devices. Add ServerAliveInterval 60 and ServerAliveCountMax 3 to your ~/.ssh/config (or pass -o ServerAliveInterval=60 on the command line) to send keepalive packets every 60 seconds and prevent timeouts.
