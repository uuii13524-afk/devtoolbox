Linux find Command Examples

The find command recursively searches directory trees for files and directories matching specified criteria. It is indispensable for locating files, auditing permissions, and running batch operations across large codebases.

Linux find CLI File System
Find by Name / Type
Find files by name pattern 
find . -name "*.log"
Searches the current directory and all subdirectories for files matching the glob pattern *.log. The dot (.) means start from the current directory. Replace with an absolute path to search elsewhere.
Find directories by name 
find . -type d -name "config"
The -type d flag restricts results to directories only. Use -type f for regular files or -type l for symbolic links. This avoids confusing file and directory matches.
Case-insensitive name search 
find . -iname "readme*"
-iname works like -name but ignores case, matching README.md, Readme.txt, readme.rst, etc. Useful when working with mixed-case file systems or codebases with inconsistent naming.
Find files with multiple extensions 
find . -name "*.py" -o -name "*.js"
The -o flag is the OR operator. This finds all Python and JavaScript files. When combining -o with actions, wrap conditions in parentheses to avoid precedence issues: find . \( -name "*.py" -o -name "*.js" \) -type f.
Find by Attributes
Find files larger than a given size 
find . -size +10M
Finds files larger than 10 megabytes. Use + for greater than, - for less than, and no sign for exact. Units: k (kilobytes), M (megabytes), G (gigabytes).
Find files modified in the last N days 
find . -mtime -7
Finds files modified within the last 7 days. -mtime -7 means less than 7 days ago. Use -atime for last access time and -ctime for last status change. Use +7 to find files older than 7 days.
Find files by permissions 
find . -perm 644
Finds files with exactly 644 permissions. Use -perm /644 to find files where any of those permission bits are set, or -perm -644 for files where all of those bits are set (and possibly more).
Find empty files 
find . -empty
Finds all empty files (0 bytes) and empty directories. Combine with -type f or -type d to restrict to only empty files or only empty directories respectively.
Execute Actions
Find and delete files 
find . -name "*.tmp" -delete
The -delete action removes matching files. Always run without -delete first to verify what will be deleted. This is faster than using -exec rm and avoids spawning a new process per file.
Find and execute a command on each result 
find . -name "*.sh" -exec chmod +x {} \;
The -exec action runs a command for each match. {} is replaced by the file path, and \; terminates the command. For better performance with many files, use + instead of \; to batch arguments: -exec chmod +x {} +.
Find files containing a pattern 
find . -name "*.py" -exec grep -l "TODO" {} \;
Combines find and grep to list Python files that contain the word TODO. The -l flag tells grep to print only the filename rather than the matching line. Consider using grep -rl "TODO" --include="*.py" . as a faster alternative.

How to Use

  1. Always start with a dry run — run the find command without any destructive action to verify results.
  2. Use -maxdepth 1 to limit the search to the current directory only and avoid deep recursion.
  3. Combine multiple criteria: find . -name "*.log" -size +10M -mtime +30 finds large, old log files.
  4. Use -exec ... + instead of -exec ... \; when possible for better performance.
  5. Redirect stderr to /dev/null to suppress "Permission denied" errors: find / -name "file" 2>/dev/null.

Frequently Asked Questions

What is the difference between find and locate?

find searches the filesystem in real-time and always returns up-to-date results. locate queries a pre-built database (updated by updatedb) and is much faster but may return stale results for recently created or deleted files. Use find when accuracy matters.

How do I exclude a directory from find results?

Use -prune to skip a directory: find . -path ./node_modules -prune -o -name "*.js" -print. This tells find to prune (skip) the node_modules directory and print all other .js files. Always pair -prune with -o ... -print to avoid odd output.

Why does find return "Permission denied" errors?

find tries to descend into every directory it encounters. When it hits directories you don't have read permission for, it prints a "Permission denied" error to stderr. Suppress these with 2>/dev/null, or run the command with sudo if you need access to those directories.
