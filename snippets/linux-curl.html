Linux curl Command Examples

curl is a command-line tool for transferring data with URLs, supporting HTTP, HTTPS, FTP, and more. It is the go-to utility for API testing, file downloads, and debugging web requests from the terminal.

Linux curl HTTP CLI
Basic Requests
Basic GET request 
curl https://api.example.com/data
Sends a GET request and prints the response body to stdout. curl defaults to GET when no method is specified. Pipe the output to jq for pretty-printed JSON: curl https://api.example.com/data | jq .
Follow redirects 
curl -L https://example.com
The -L flag tells curl to follow HTTP 3xx redirects automatically. Without it, curl stops at the redirect response. Most download URLs and short links require this flag.
Verbose output (debug mode) 
curl -v https://example.com
The -v flag prints detailed information including the request headers, response headers, TLS handshake, and response body. Essential for debugging API issues or inspecting what headers are being sent.
Show only response headers 
curl -I https://example.com
The -I flag sends a HEAD request and displays only the response headers. Useful for checking HTTP status codes, content types, cache headers, and server information without downloading the body.
POST and Data
POST JSON data 
curl -X POST \
  -H "Content-Type: application/json" \
  -d '{"key": "value"}' \
  https://api.example.com/endpoint
Sends a POST request with a JSON body. The -H flag sets the Content-Type header, and -d provides the request body. Always set Content-Type to application/json when sending JSON data.
POST form data 
curl -X POST -d "user=foo&pass=bar" https://example.com/login
Sends URL-encoded form data, equivalent to submitting an HTML form. curl automatically sets Content-Type: application/x-www-form-urlencoded when using -d without an explicit Content-Type header.
Bearer token authentication 
curl -H "Authorization: Bearer YOUR_TOKEN" https://api.example.com/protected
Sets the Authorization header with a Bearer token, used by most modern REST APIs. Replace YOUR_TOKEN with your actual token. Store tokens in environment variables and use -H "Authorization: Bearer $TOKEN" to avoid exposing them in shell history.
Files and Output
Download a file (keep original name) 
curl -O https://example.com/archive.zip
The -O flag saves the file using the filename from the URL. The file is saved in the current directory. Combine with -L if the URL redirects: curl -LO https://example.com/file.zip.
Save with a custom filename 
curl -o myfile.zip https://example.com/archive.zip
The lowercase -o flag saves the output to the specified filename. Unlike -O, you control the destination name and path. Useful when the URL filename is generic or unclear.
Upload a file 
curl -F "file=@local.txt" https://api.example.com/upload
The -F flag sends a multipart form-data request, the standard way to upload files via HTTP. The @ prefix tells curl to read the file from disk. Add additional form fields with more -F flags.
Set a request timeout 
curl --max-time 10 https://example.com
Aborts the request if it takes longer than 10 seconds. Use --connect-timeout 5 to set a separate timeout for the connection phase. Always set timeouts in scripts to prevent hanging indefinitely on unresponsive servers.

How to Use

  1. Start with a simple GET request to verify connectivity before adding authentication or request bodies.
  2. Use -v or -i (include response headers) when debugging to see the full request/response cycle.
  3. Store API tokens in environment variables and reference them with $VARIABLE to keep credentials out of your shell history.
  4. Use -s (silent) to suppress the progress meter in scripts, combined with -S to still show errors.
  5. Pipe JSON responses to jq for readable formatting and field extraction.

Frequently Asked Questions

What is the difference between curl -d and curl -F?

-d sends data as application/x-www-form-urlencoded (plain key=value pairs), which is used for simple form submissions and JSON bodies. -F sends data as multipart/form-data, which is required for file uploads. Use -F whenever you need to upload binary file content.

How do I ignore SSL certificate errors with curl?

Use the -k or --insecure flag to skip certificate verification: curl -k https://self-signed.example.com. This is useful for testing with self-signed certificates in development, but should never be used in production scripts as it disables all SSL security checks.

How do I save cookies and send them on subsequent requests?

Use -c cookies.txt to save cookies to a file after the first request, and -b cookies.txt to send those cookies on subsequent requests. This mimics browser session behavior for testing login flows: curl -c cookies.txt https://example.com/login -d "user=foo&pass=bar" then curl -b cookies.txt https://example.com/dashboard.
