Contact Dev Toolbox

We welcome bug reports, tool requests, and feedback from the developer community. Here is how to reach us.

Ways to Get in Touch

Preferred

GitHub Issues

The best way to report a bug, request a new tool, or suggest an improvement is to open an issue on our GitHub repository. Issues are publicly visible so others can upvote features they also want.

Contributions

Pull Requests

What to Include in a Bug Report

A good bug report helps us fix the issue quickly. Please include:

  • Which tool is affected (e.g., "JSON Formatter")
  • What you expected to happen
  • What actually happened
  • Your browser and operating system (e.g., Chrome 124 on Windows 11)
  • A sample input that reproduces the problem (if applicable)

Tool Requests

Have a tool you wish Dev Toolbox had? Open a GitHub issue with the label feature request and describe:

  • What the tool should do
  • When you would use it in your workflow
  • Any existing tools or websites that do something similar

We prioritize tools that are commonly needed, work well client-side, and benefit a broad range of developers.

Frequently Asked Questions

How quickly will you respond to issues?

We aim to acknowledge all issues within a few days. Bug fixes and new tool additions are typically shipped within one to two weeks, depending on complexity.

Can I request a tool that processes data server-side?

Dev Toolbox is designed around the principle that all processing happens client-side in the browser. We generally avoid tools that require server infrastructure, both to protect user privacy and to keep the site fast and free to operate.

I found a security issue. How should I report it?

Please report security vulnerabilities privately rather than in a public GitHub issue. Open a GitHub issue marked as "Security" or use GitHub's private vulnerability reporting feature so we can address it before it is publicly disclosed.

Can I use Dev Toolbox tools in my own project?

The source code is available on GitHub. Please check the repository license before incorporating any code into your own project. We are generally open to reuse with attribution.
